API Reference

Build & Deploy

Ba con đường ra sản phẩm: build 3DS thật (.3dsx/.cia), build desktop độc lập, và chạy Play-in-Editor. Xem Cài đặt & Build cho lệnh dòng lệnh cơ bản — trang này đi sâu vào cơ chế bên dưới.

BuildPipeline (Editor)

static void BuildFor3DSAsync(const std::string& repoRoot, const std::string& scenePath)

Chạy trên thread nền riêng (không block UI Editor lúc build tới gần 1 phút) — copy scene khởi động vào DualityPlayer/romfs/Scene.scene (Start Scene lấy từ Build Settings nếu đã cấu hình, xem mục "Cook asset lên romfs" bên dưới) rồi tự chạy build-3ds.bat. Cook asset (texture...) qua tex3ds, đường dẫn không hardcode — tự tìm theo thứ tự: biến môi trường DEVKITPRO (chỉ nếu trỏ tới đường dẫn Windows thật) → registry key devkitProUpdater devkitPro cài lúc setup → mặc định C:\devkitPro. Không tìm được thì bỏ qua bước cook texture (log cảnh báo rõ), không fail cả build.

static void BuildForPCAsync(const std::string& buildDirectory)

Nhẹ hơn nhiều — chỉ rebuild incremental target DualityPlayerDesktop trong cây build desktop có sẵn. Không có bước cook romfs/asset nào, vì target này đọc thẳng Assets/ từ đĩa mỗi lần khởi động. Dùng chung một cờ trạng thái với BuildFor3DSAsync — hai build không chạy đồng thời được (cùng đụng vào cây build Ninja).

Cả hai gọi được từ Editor (menu File → Build for 3DS/Build for PC) hoặc dòng lệnh trực tiếp qua build-3ds.bat/ build.bat — hai con đường dùng chung logic, không phân nhánh.

Cook asset lên romfs (3DS)

Mọi file không phải .png trong Assets/ được copy nguyên văn vào romfs kèm một manifest — không cần cấu hình gì thêm khi thêm asset type mới, kể cả một file scene thứ hai cho SceneManager.LoadScene nhắm tới (miễn scene đó có mặt trong Build Settings, một khi project đã cấu hình danh sách này — xem ngay bên dưới).

Build Settings quyết định scene nào lên máy thật

ProjectConfig::ScenesInBuild — danh sách scene cấu hình qua panel Build Settings trong Editor (xem Editor Panels để biết cách thêm/xoá/sắp xếp) — là danh sách đường dẫn scene tính từ Assets/, theo đúng thứ tự build; phần tử đầu tiên (ScenesInBuild[0]) là Start Scene. Danh sách này thay đổi cả bước cook romfs lẫn scene nào được đóng gói làm boot scene:

  • Danh sách rỗng (project chưa từng mở Build Settings) — hành vi y hệt trước khi có tính năng này: mọi scene dưới Assets/ đều được cook vào romfs không lọc gì, và Scene.scene đóng gói cho build 3DS là bất kỳ scene nào đang mở trong Editor lúc bấm Build (được lưu lại ngay trước đó).
  • Danh sách không rỗng — CookAssets chỉ copy vào romfs/Assets/... những file .scene có mặt trong ScenesInBuild; mọi scene khác dưới Assets/ bị loại khỏi romfs hoàn toàn dù vẫn nằm trên đĩa của project. Đồng thời, Scene.scene đóng gói cho build 3DS đổi thành chính xác ScenesInBuild[0] — không còn phụ thuộc scene nào đang mở trong Editor nữa.

Cùng quy ước Start Scene đó cũng quyết định scene khởi động của DualityPlayerDesktop (xem mục riêng bên dưới) — nhưng vì desktop không có bước cook nào, danh sách này chỉ đổi scene nào được đọc lúc mở game, không lọc/loại bỏ file nào trên đĩa như bên 3DS.

Scene "biến mất" trên máy 3DS thật Một scene không được thêm vào Build Settings vẫn chạy bình thường trong Editor và trên DualityPlayerDesktop — không nơi nào trong hai chỗ đó lọc theo ScenesInBuild. Nhưng ngay khi Build Settings đã được cấu hình (danh sách không còn rỗng nữa, dù chỉ thêm đúng một scene), scene bị bỏ sót sẽ không có mặt trong romfs của build 3DS — một SceneManager.LoadScene nhắm tới nó trên máy thật sẽ thất bại vì file không tồn tại. Nhớ thêm mọi scene thật sự cần dùng vào Build Settings trước khi build 3DS, kể cả scene chỉ được load động lúc runtime chứ không phải Start Scene.

Chưa chọn gì (hoặc file không còn tồn tại) thì rơi về placeholder Packaging/icon.png có sẵn của engine, y hệt hành vi trước khi field này tồn tại.

Vòng lặp Play-in-Editor

Không cần build lại executable để thử code gameplay: sửa GameScripts/*.cpp, bấm Reload Scripts (panel Game) — chỉ GameScripts.dll được rebuild + hot-reload vào Editor đang chạy. Giống BuildFor3DSAsync/BuildForPCAsync ở trên, việc rebuild chạy trên một thread nền riêng (ScriptEngine::ReloadAsync) — UI Editor không đứng hình trong lúc build, nút chỉ đổi thành "Reload Scripts (reloading...)" và tự disable tới khi xong. Trên desktop, GameScripts build dạng SHARED (DLL); trên 3DS, cùng bộ source build dạng STATIC, link thẳng vào DualityPlayer (không có dynamic loading trên phần cứng).

DualityPlayerDesktop

Runtime desktop độc lập, không kèm Editor/ImGui — một cửa sổ GLFW thật, vẽ cả hai màn xếp chồng dọc (giống cách cầm máy 3DS thật) vào cùng một framebuffer mặc định qua glViewport/glScissor riêng cho mỗi màn. Chạy cùng pipeline Scene/SceneSerializer/ AssetDatabase/GameScripts y hệt 3DS thật — chỉ khác backend renderer (OpenGL thay vì citro2d/citro3d). Hiện luôn chạy SampleProject cố định (chưa có project picker) và tỉ lệ 2x cố định. Không có bước cook/đóng gói nào — đọc thẳng Assets/ của project trên đĩa mỗi lần khởi động, nên Build Settings không lọc hay ẩn file scene nào ở đây như bên 3DS.

Scene mở lúc khởi động là ScenesInBuild[0] (Start Scene) nếu project đã cấu hình Build Settings, hoặc file Scene.scene ở gốc Assets/ (hành vi hardcode gốc) nếu danh sách còn rỗng — cùng quy ước Start Scene mà BuildFor3DS dùng để chọn boot scene cho build 3DS (xem mục "Cook asset lên romfs" ở trên). Mọi scene khác trong project vẫn load được bình thường qua SceneManager.LoadScene lúc runtime — đây chỉ là scene ban đầu, không phải một whitelist.

Testing

run-tests.bat

Test suite headless cho logic engine cốt lõi (không cần GUI/thiết bị) — link trực tiếp compiled code thật của DualityEngine, không mock. Bộ TEST_CASE/CHECK tự viết nhỏ gọn (Tests/TestFramework.h) thay vì vendor Catch2/GoogleTest. .github/workflows/ci.yml chạy build.bat + run-tests.bat trên mỗi push/PR (chỉ desktop — cross-compile 3DS chưa nối vào CI).
