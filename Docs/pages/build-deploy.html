API Reference

Build & Deploy

Ba con đường ra sản phẩm: build 3DS thật (.3dsx/.cia), build desktop độc lập, và chạy Play-in-Editor. Xem Cài đặt & Build cho lệnh dòng lệnh cơ bản — trang này đi sâu vào cơ chế bên dưới.

BuildPipeline (Editor)

static void BuildFor3DSAsync(const std::string& repoRoot, const std::string& scenePath)

Chạy trên thread nền riêng (không block UI Editor lúc build tới gần 1 phút) — copy scene hiện tại vào DualityPlayer/romfs/Scene.scene rồi tự chạy build-3ds.bat. Cook asset (texture...) qua tex3ds, đường dẫn không hardcode — tự tìm theo thứ tự: biến môi trường DEVKITPRO (chỉ nếu trỏ tới đường dẫn Windows thật) → registry key devkitProUpdater devkitPro cài lúc setup → mặc định C:\devkitPro. Không tìm được thì bỏ qua bước cook texture (log cảnh báo rõ), không fail cả build.

static void BuildForPCAsync(const std::string& buildDirectory)

Nhẹ hơn nhiều — chỉ rebuild incremental target DualityPlayerDesktop trong cây build desktop có sẵn. Không có bước cook romfs/asset nào, vì target này đọc thẳng Assets/ từ đĩa mỗi lần khởi động. Dùng chung một cờ trạng thái với BuildFor3DSAsync — hai build không chạy đồng thời được (cùng đụng vào cây build Ninja).

Cả hai gọi được từ Editor (menu File → Build for 3DS/Build for PC) hoặc dòng lệnh trực tiếp qua build-3ds.bat/ build.bat — hai con đường dùng chung logic, không phân nhánh.

Cook asset lên romfs (3DS)

Mọi file không phải .png trong Assets/ được copy nguyên văn vào romfs kèm một manifest — không cần cấu hình gì thêm khi thêm asset type mới, kể cả một file scene thứ hai cho SceneManager.LoadScene nhắm tới.

Vòng lặp Play-in-Editor

Không cần build lại executable để thử code gameplay: sửa GameScripts/*.cpp, bấm Reload Scripts (panel Game) — chỉ GameScripts.dll được rebuild + hot-reload vào Editor đang chạy. Giống BuildFor3DSAsync/BuildForPCAsync ở trên, việc rebuild chạy trên một thread nền riêng (ScriptEngine::ReloadAsync) — UI Editor không đứng hình trong lúc build, nút chỉ đổi thành "Reload Scripts (reloading...)" và tự disable tới khi xong. Trên desktop, GameScripts build dạng SHARED (DLL); trên 3DS, cùng bộ source build dạng STATIC, link thẳng vào DualityPlayer (không có dynamic loading trên phần cứng).

DualityPlayerDesktop

Runtime desktop độc lập, không kèm Editor/ImGui — một cửa sổ GLFW thật, vẽ cả hai màn xếp chồng dọc (giống cách cầm máy 3DS thật) vào cùng một framebuffer mặc định qua glViewport/glScissor riêng cho mỗi màn. Chạy cùng pipeline Scene/SceneSerializer/ AssetDatabase/GameScripts y hệt 3DS thật — chỉ khác backend renderer (OpenGL thay vì citro2d/citro3d). Hiện luôn chạy SampleProject cố định (chưa có project picker) và tỉ lệ 2x cố định.

Testing

run-tests.bat

Test suite headless cho logic engine cốt lõi (không cần GUI/thiết bị) — link trực tiếp compiled code thật của DualityEngine, không mock. Bộ TEST_CASE/CHECK tự viết nhỏ gọn (Tests/TestFramework.h) thay vì vendor Catch2/GoogleTest. .github/workflows/ci.yml chạy build.bat + run-tests.bat trên mỗi push/PR (chỉ desktop — cross-compile 3DS chưa nối vào CI).
